# Build

"I'll build to understand." — not "I'll reinvent what exists."

- What do I need to implement to test my understanding?
- Am I building a complete implementation, a simplified implementation, a prototype, a component, an experiment, a subsystem, an algorithm, or a protocol implementation?
- What's the appropriate scope for this build? (You decide the scope — Foundry doesn't require building the whole system)

While building, record what shows up that reading alone didn't reveal:

- What problem in the design did you discover?
- What trade-off wasn't obvious?
- What limitation or edge case did you run into?
- Was the performance different from what you expected?
- What's the reason behind an architectural decision in the original project that you now understand?
- What better way did you find to implement a particular part?

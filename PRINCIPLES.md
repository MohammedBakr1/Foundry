# PRINCIPLES

The philosophy of Foundry can be summarized in a set of principles:

## Start from what exists

Begin from existing knowledge.

## Understand before extending

Understand before trying to build on top of what exists.

## Build when building teaches

Build when building is an effective way to learn.

## Don't reinvent blindly

Don't rebuild what exists just to rebuild it.

## Learn from implementation

Implementation itself is a source of knowledge.

## Validate your understanding

Don't rely on the feeling that you understood.

## Document what you discover

Turn the experience into knowledge you can return to.

## Develop what has value

If the result deserves to continue, develop it.

## Contribute what can help others

If the knowledge or result is useful to the community, contribute it.

## Understand what you use, even if AI wrote it

AI tools can now write working code quickly. Foundry treats this the same way it treats any existing implementation: a reference, not a boundary. Using AI to write code doesn't exempt you from the core question — if you can't explain a decision in your own words, or don't know when it will fail, you haven't understood it yet, regardless of who or what wrote it.

## Return to Open Source

Knowledge doesn't stop with the individual.

---

## Principles + Process + Evidence

Foundry can be built on three pillars:

```
        FOUNDRY
           │
    ┌──────┼──────┐
    ↓      ↓      ↓
Principles Process Evidence
```

- **Principles** — why do we do this?
- **Process** — how do we do it?
- **Evidence** — how do we know we actually learned?

This is better than turning Foundry into a rigid tutorial.

# Contributing to Foundry

Contribution isn't necessarily just a pull request. It can be:

- Code
- Patch
- Feature
- Optimization
- Tool
- Documentation
- Bug fix
- Research result
- Architectural idea

## Contributing a Case Study

If you applied the Foundry methodology to your own project, you can add it to `case-studies/` following the same file structure as the existing entries (Define → Explore → Understand → Build → Investigate → Validate → Reflect → Develop/Contribute).

## Contributing an Improvement to the Methodology Itself

Foundry isn't a fixed method from day one — it evolves through use. If you find that a particular stage is unnecessary, or that a question is missing, open an issue or discussion explaining:

- Which stage are you talking about?
- What problem did you run into with the current version?
- What's your proposed change?

## Contributing to the Template

If you have a suggestion to improve `templates/project/`, explain how the change serves the core principle: that the files are questions and prompts, not lessons.
